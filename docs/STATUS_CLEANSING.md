# 公共负面状态净化

## 当前玩法（2026-09-27）

- 雪傀儡基础最大生命 **425**，其他数值不变。半血判定仍是当前最大生命的 50%；整数生命下，213 尚未碎头，212 会触发一次碎头并保证下一轮连射。
- 铜剑只在锈满后召来的**自然雷实际命中时**调用 `ball.cleanse_negative_effects()`；预警、暂停、失效/禁用技能、死亡、非权威端与攻击召雷均不额外净化。
- 清除的是自身**负面**持续效果及其所有来源，而不是全部药水。力量、抗性、迅捷、隐身、吸收等正面状态保留原节点、来源、等级和剩余时长。瞬间伤害已经造成的扣血不会被回滚；净化不是治疗，也不是免疫窗口。
- 灼烧、寒冷/冻结、减速/虚弱/中毒/凋零等负面药水、旧流血/燃烧、Karma、敌方击退/眩晕/真实击飞、黏附和箭伤标记共用同一规则。待执行箭伤斩杀会取消，不能在移除后通过旧回调补杀。仍在场的伤害地面或后续新命中可以重新施加状态。
- 蜂蜜抓取是施术者持有的外部控制记录：监听公共净化信号，结束本次抓取、成对免碰撞和撞墙伤害回调；按原抓取规则，须离开后再进入才可重抓。不是修改蜂蜜时长/拉速/伤害。

## 新状态必须遵循的协议

不能从任意未来脚本的名字、图标颜色或私有变量可靠推断正负效果。新状态应在自己的公共注册/协议中声明一次，**不得再给铜剑添加脚本名或效果名特判**。

### 节点型状态

1. 在 `combat_classification_catalog.gd` 的身份或阶段中声明 `entity_kind: "status"`，并声明：
   - `status_polarity`: `negative` / `positive` / `neutral` / `dynamic`。
   - `status_cleanup`: `detach` 或该节点已有的无参清理方法名。
2. 动态正负状态实现 `get_status_effect_polarity() -> int`：负数有害、零中性、正数有益。女巫药水直接使用公共 `mc_status_effects.SPECS.sign`；新药水只需在同一目录中定义其符号，不改净化消费者。共享击退根据敌方控制/自主运动区分，物理击飞继承同一协议。
3. 自定义清理可实现 `cleanse_status_effect() -> void`，优先于登记的旧结构适配方法。须停止自己持有的 DOT、Buff、物理/碰撞/引力租约、信号、Tween/延迟回调和持续视觉；只释放自己的所有权，不直接清空受击者的全部控制锁或设置 `dizziness=false`。清理应幂等。
4. 状态放在受影响角色的子树中（允许 Graphics 等中间层）。外部独立持有的节点使用 `victim.register_status_effect(effect)` 注册弱引用，若持有 `target` 字段，该字段必须指向受影响者；多目标效果应为每名受影响者建立独立状态/租约。不能把另一个角色本体注册成可删除状态。
5. 外部数据型控制者可监听 `victim.negative_effects_cleansed`，在回调中释放自己的负面记录。结束关系/退出时必须断开监听；蜂蜜抓取是现有范例。共享牵引在净化时移除外部贡献，保留中性自主贡献。
6. 阶段身份必须准确：嵌入身体的骷髅箭是状态；飞行箭和插墙箭仍是投射物/地形，不因靠近角色或父节点相同而删除。

协议方法也支持程序运行时创建的状态；测试以此前不存在的合成负面、正面、中性及外部状态验证，无需改铜剑或中央效果名名单。其他角色的子树不会因挂在受净化者之下而被递归删除。

### 数值 Buff

- `Buff.effect_polarity = -1` 显式有害，`+1` 显式有益；默认 `0` 使用公共数值语义。
- 加法、乘法和 Set 均以 `BENEFIT_DIRECTION` 判断；冷却增加为负面，攻击/速度/减伤等降低为负面。Set 对照当前默认属性。中毒与寄生本身为负面。
- 新增 `Buff_types` 必须增加其语义或明确正负符号；不要依赖中文 Buff 名。登记检查会拒绝缺少语义的新枚举。
- 负面条目直接移除，不走自然到期伤害，尤其不能让“寄生”在净化时爆炸。混合来源字典中的正面条目仍保留。
- 属性即时恢复复用 `world.refresh_runtime_buffs()` 与正常帧的 `_apply_runtime_property_buff()`；它不推进持续时间、全局中毒计时或伤害，不用 `figure_buffs(0)` 假装刷新。

## 生命周期与同步

- 本地清理先倒序释放较新的状态所有者，再立即移出树、最后排队释放，保证控制/属性/稳定节点名在当前帧就解除，可立即正常重施。
- 公共 API 只允许存活角色的权威端发起。可靠 RPC 走稳定的角色节点，不向即将销毁的状态子节点发 RPC；每端以递增版本幂等处理。重复/旧净化包不会清除之后新施加的效果。
- 正面效果、其他角色、装备/附魔目录、船乘坐、表面加速、自主反冲等不被当作负面状态删除。纯粒子允许自然寿命结束；不抹除已发生的攻击、场景地形或伤害。
- 当前注册表检查覆盖所有脚本/场景身份、状态阶段正负声明、动态查询和清理方法（含继承），以及全部 Buff 枚举的极性语义。新增状态须通过 `python tests/verify_combat_classification_registry.py`，不能漏登记后声称自动净化。
