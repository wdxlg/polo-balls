# 传送门组：原生 TileMap 编辑

## 创建及设置

- 在 `PortalMap` 下添加 `PortalTiles` 节点，或复制现有组并清空笔触。
- 一个瓦片层是一组互通门；不同层之间完全独立。
- 自定义设置只有两项：`pass_mode`（都通过 / 仅角色 / 仅子弹）和 `direct_connection`（直接连通）。
- 用 Godot 原生 TileMap 面板选择蓝色或红色方块，沿地图外侧逐格画、擦。原生撤销可用。
- 红蓝仅是编辑用的路由分类。局内每个 TileMapLayer 使用一种稳定的伪随机颜色，同组所有门线、粒子和传送反馈同色；重建或切换地图不会闪变颜色。
- 岛屿与组应对齐到同一格网。无需设置来源岛、目标岛、朝向、长度、镜像或双向。

## 什么是一扇门

同色方块上下左右连接的一片色块算一扇门；分开的色块是不同的门。
斜角相邻不算连接。相邻但颜色不同也属于不同门。门可以画在同一岛的不同边上。
角度由接触到的地图边界计算。较长的门不会得到更高的随机目标权重。

## 连接规则

| 有效门布局 | 行为 |
| --- | --- |
| 只有蓝色，或只有红色，至少两扇门 | 每次随机去另一扇同色门，不回自身 |
| 同时有蓝色和红色 | 蓝色随机去红色，红色随机去蓝色 |
| 只有一扇门，直连关闭 | 不生效 |
| 只有一扇门，直连开启，但只接触一片地图 | 不生效 |
| 直连开启，单个色块同时接触两片地图 | 该色块将两侧直接双向接通，不要求另画一个门 |

有效直连优先于远程随机路由；不满足直连条件的其他门继续遵循颜色规则。
目标过窄、放不下当前角色或子弹时，不会强行把它塞进墙里。
无效/未配对的单门可在场景树看到配置警告，不会自动恢复旧参数。

## 命名示例

- `Map_Portal/Portal_Characters`：角色通过的一组门。
- `Map_Portal/Portal_Projectiles`：子弹通过的一组门（可按需创建）。

原来的入口/出口子层已合并。旧 PortalLink 字段只保留为隐藏的兼容迁移数据，不再用于新门的配置。
