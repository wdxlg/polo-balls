## 本次：与游戏颜色一致，剔除 Esc 暂停与恢复等待

- 旧离屏视口强制 SDR，虽然不透明色卡能通过，但与主窗口 HDR 2D 的半透明混合结果不同，且遗漏 Game 常驻暗角。现在共享主窗口的 HDR/抗锯齿/像素对齐设置，只复制常驻暗角；不复制 `Stop_Ui`、工具栏或模拟遮罩。
- HDR 画面先在 GPU 以浮点精度转换到 sRGB，再读回 RGBA8；不先量化 HDR 再补 gamma，避免暗部丢失。录制暗角使用正常对战 SCALE，不跟随暂停/恢复的变暗动画。
- 暂停门控同时检查 SceneTree、Game 状态、暂停/倒计时 UI；Esc 边界加锁存，恢复时必须已有本轮新渲染，禁止使用暂停前或暂停期间的旧纹理。音频与视频使用同一个跳过条件；不累加等待时间。
- **右键不是回放旧录像**：它用已有布阵重新模拟一场，以 0.25 倍速降低采集压力，再按正常游戏速度和音调输出；随机和物理结果不保证与刚才那局完全相同。左键才是录当前正在进行的对战，再点一次停止。

## 当前行为

- **左键 LIVE**：开始/停止实时对战录制。**右键 SIM**：重打已有布阵，0.25 倍速模拟，按正常游戏时间输出有声视频。SIM 仅支持本地对局。
- 两种方式都使用独立 `SubViewport` 原生渲染 **1080×1920 / 60fps**。不抓 540×960 小窗口再放大。输出 H.264 / CRF 14 / yuv420p / BT.709，AAC 48kHz 双声道，目标 320kbps。
- 只共享战斗 `world_2d`，保留场地、人物、投射物、血量、伤害数字、上下队列与现有水印。工具栏、原生鼠标、选区、FPS、Esc 暂停时间条、设置面板和模拟遮罩不进片。
- 主窗口照常显示并使用 UI，不是先隐藏主窗口 UI 再截图。暂停及队伍布阵时，画面和音频同时停止写入；恢复后接续，不把等待时间放进成片。
- 显示录制中/保存中/错误原因；结束可打开输出文件夹。路径使用只读 LineEdit，避免全局翻译器误改 `Godot` 路径。
- 输出目录：`user://recordings`，Windows 一般是 `%APPDATA%/Godot/app_userdata/polo_balls/recordings`。

## 实现要点

- `scripts/ui/battle_recorder.gd`：渲染、帧时钟、编码、结束判定及清理。
- `scripts/ui/battle_record_audio.gd`：只在 GameplayRecord 总线上追加临时 AudioEffectCapture；声音流式写入 f32 stereo PCM，不将整场音频累积在内存。移除时按实例匹配，仅清理自己的 effect。
- `scripts/ui/battle_record_controls.gd`：按钮状态、提示与结果窗口。
- UI 音频走现有独立 UI 总线，不经过游戏录音入口；不采集麦克风或桌面声音。
- 既有 Audios 会令游戏声音跟随 Engine.time_scale；SIM 采集以同一倍率重采样，抵消模拟慢放，恢复正常音高。尊重游戏总线和 Master 的音量/静音设置，不改动用户混音设置。
- 对战画面采用与主窗口一致的 HDR/SDR 渲染，HDR 时用额外的 GPU sRGB 解析视口输出 RGBA8；透明混合、暗角与暗色不依赖猜测 gamma。
- 根据逻辑视口映射相机，不使用 Window 纹理的缩放后尺寸再次缩放相机。小窗口与原生输出构图一致。
- 掉帧补帧使用上一张画面，而不是把新命中/闪光提前填入过去的时间段。严重渲染阻塞或音频缓存溢出明确停止，不静默缩短视频导致漂移。
- 先输出视频临时文件与 PCM，再复制视频流、仅编码音频完成合成。成功后删除临时文件；合成失败保留恢复材料并报错。
- 没有可用 ffmpeg 时仍能降级为 PNG 序列与独立 PCM，**不能把该降级产物称为已经合成的有声 MP4**。
