# 录制修复（2026-09-23）

## 原因与修改

`ui/control.tscn` 已经放置 Record 按钮，连接到 `_on_record_button_up` / `_on_record_button_gui_input`，但 `ui/control.gd` 不再实现这两个回调，也没有创建 `battle_recorder.gd`。本次恢复回调及实例化，录制状态/保存弹窗集中在 `scripts/ui/battle_record_controls.gd`。

- 左键：实时录制，再左键停止；录制时红色，保存中禁用重复启动。按钮和录制器在场景暂停时仍工作。
- 右键：有布阵且为本地对局时，慢速重打并离屏输出；队列换人间隙不作为整场终点；结束后自动保存，也可中止并保存已录部分。
- 无布阵、无渲染环境、权限不足、编码写入失败等会反馈原因，不再只静默返回 false。
- 停止后恢复时间倍率、游戏总线静音状态，并清理遮罩和离屏视口。
- 保存弹窗显示文件位置并提供“打开输出文件夹”；路径用只读 LineEdit，避免现有全局翻译器把路径中的 `Godot` 错译。
- ffmpeg 缺失时保留原 PNG 序列降级功能；补充奇数尺寸合成处理、编码结果判断与超时进程终止。

## 使用与限制

- 默认输出：`user://recordings`，Windows 通常为 `%APPDATA%/Godot/app_userdata/polo_balls/recordings`。
- LIVE 为 30 fps；SIM 为 60 fps、0.25 倍速模拟再按正常速度输出。
- **两种模式当前均为无音轨视频。** 原编码参数为 `-an`，本次没有实现音频采集/同步，不要宣称游戏音效已经录入。
- 修改后重新运行游戏实例即可。无需修改编辑器权限、重装 ffmpeg 或重载 MCP。
- SIM 是重打已有布阵，不是历史录像回放；不保证所有物理与随机行为完全确定。
- 原抓帧实现仍有长卡顿补帧上限；没有验证低性能设备、大规模高负载长时间录制或双客户端。

使用本机 Godot 4.7.2、RTX 4060 Laptop GPU：

- `tests/test_battle_recording.gd` headless：9 项通过（接线、失败提示等，不是视频输出验证）。
- 同一脚本 D3D12 Forward+ 实际渲染：32 项通过。通过视口投递真实鼠标按下/松开事件检查左右键；暂停停止、离屏抓帧、遮罩、中止、自动结束与状态恢复均覆盖。
- 真实 World 场景，SIM 使用轻量 ball 布阵；自动结束测试设置系列完成标志，不是所有角色完整长局测试。
- 3 个实际输出的 H.264 MP4（LIVE / SIM 中止 / SIM 自动结束）使用 ffprobe 核对帧数与帧率，并用 ffmpeg 全帧解码成功；540×960，分别 30/60/60 fps，无音轨。

- `ui/control.gd`、录制后端与 UI 适配脚本诊断均无 error。
- 原项目已有 shader UID / `set_rgb_color` 大小写警告，未在本任务中修改。
