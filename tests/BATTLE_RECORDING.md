# 对战录制（2026-09-23，从当前状态离线计算）

## 当前右键定义（取代旧版 0.25 倍重打）

用户明确纠正：右键必须从点击瞬间的完整状态继续，不能按布阵重开。已移除 `request_world_rematch` 与固定 0.25 倍采集，采用同一进程、同一世界的原生离线时钟。用户选择速度与质量优先，不要求计算后还原原局；本版结束/中止后暂停在算到的位置，可按 Esc 继续。

### 启动

- 项目根目录 **`启动离线录制版.cmd`**：使用独立 Godot 4.7.2 运行项目。
- **`启动离线版编辑器.cmd`**：可选的独立编辑器入口；不要让两个编辑器同时编辑同一项目。
- Steam 原版及已有进程未覆盖、未关闭。旧进程不能热切换引擎；原版仍支持左键，右键会明确提示换入口，绝不退回重打。
- 源码补丁、SHA-256、构建和使用方法见 `tools/offline_engine/`。二进制在项目外 `E:/godot/polo-balls-tools/offline-engine/runtime/`。

### 当前实现

- 没有序列化重建另一局。原角色、飞行物、生命、位置、速度、脚本执行状态和现存计时器原地继续。
- 固定 60fps 离线时间：一帧完成后才推进下一帧。等待编码不增加游戏/视频时间，不通过重复旧画面填满计算耗时。
- 原生离线混音沿用当前音频流/解码器；视频每帧拉取精确采样数，包含 GameplayRecord，不录 UI。硬件音频不在后台另行推进声音。
- 项目中许多技能依赖 `Time.get_ticks_*`，因此离线时也改为连续虚拟时钟；结束保持绝对冷却时间戳连续。真实编码超时使用 `Time.get_wall_ticks_*`，不受虚拟时钟影响。
- 用户基础倍速临时规范为 1x，技能自身的时间覆写保留；结束恢复用户倍速。窗口只画进度面板，最小化仍生成离屏帧；取消、暂停、场景退出有清理路径。
- 中英文仍共享一次计算与同一音频；命名保持“中文/英文”前缀 + 相同中文后缀。
- 这不是只计算一个胜负数字。完整高质量视频必须绘制各帧，耗时取决于人物/特效、GPU 读回与双路编码，**不承诺比实时更快**；但不再固定花四倍时间，也不把慢计算导出成慢动作。五分钟视频时间为安全上限，无终局时可中止保存片段。

## 两种模式共同保留的规则

- 原生 **1080×1920 / 60fps**，仅对战画面和 GameplayRecord 游戏音轨；排除鼠标、工具栏、暂停和恢复倒计时 UI 及其 UI 声音。保留主窗口 HDR/sRGB 转换和常驻暗角；半透明效果不因错误 Alpha 处理而变暗。
- 暂停、布阵等待不计入成片；录制中或收尾时不能修改目录。设置 → 录制可选择并持久记忆目录，支持中文/空格并校验可写性。默认 `user://recordings`。面板仅保留「打开」（打开保存文件夹）和「设置」（选择路径）两个按钮，手输路径按回车即保存。
- 每次同一世界、同一时间线输出两份有声 MP4，不分别打两场。两路视口各自替换可翻译的文字；共享同一份游戏音频。
- 命名为 `中文_<中文模式和中文对阵>_<时间戳>.mp4` 和 `英文_<相同中文后缀>.mp4`，不使用 `English_` 前缀。随机队伍按人数命名；录制开始时固定命名信息，不随角色死亡改名。
- 优先硬件 H.264，必要时使用软件编码。编码线程有内存上限。LIVE 保留实时行为和过载错误提示，不因右键方案改成固定帧；离线则在队列满时等待，不跳过物理帧。
- 真正导出完整过程必须计算和渲染所有帧；视频正常速度不等于保证计算速度超过实时。
