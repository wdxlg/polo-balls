## 右键提速与天堂陨落长弓裂缝（2026-09-24）

- 真实 GPU 实测表明瓶颈不是编码队列：原离线画面每帧两次 `ViewportTexture.get_image()` 加 `Image.get_data()`，两路 1080×1920 同步读回约 **15–18ms/帧**，编码队列等待通常不到 **0.1ms/帧**。现在仅在渲染设备提供 RGBA8、可读回的离屏输出时，直接取同一帧的 RenderingDevice RGBA 字节送入原编码队列；不支持的后端沿用旧 `Image` 路径，PNG 回退仍可用。不减少画幅、帧数、语言或音频，也不跳过物理步。真实画面的新旧原始 RGBA 字节逐字节相等。
- 同机独立 GPU 引擎、NVENC、121 帧/2.0167 秒的简单离线基准：原实现实际计算约 **2.86 秒**，现在约 **1.48 秒**；读回从 **15.9–17.4ms/帧** 降为约 **5.3–6.3ms/帧**。每物理步故意阻塞 40ms 的基准由约 **7.25 秒** 到 **5.79 秒**，说明耗时来自真实计算时不应误报“全局加速近两倍”。重特效对局还取决于 GPU 绘制与编码吞吐，不保证快于实时。
- 长弓裂口的星空网格本身会生成，但它上方的 screen-reading 折射材质把裂口像素重新采样成了旧背景；主/录制视口的 backbuffer 复制范围不一致时更明显。折射 shader 现在直接 `discard` 开口内部像素，让下层真实星空裂缝透出，仍保留开口外原来的折射。GPU 对照中，录制视口固定测试区域的明显变化像素从约 **153** 增至 **551**；最终 sRGB 画面约 **432**。真实长弓右键导出的中文 MP4 抽帧可见裂缝，英文离屏视频源也通过独立像素断言。

### 启动

- **原版 Godot 编辑器工具栏「▶ 运行右键录制版」**：无需切换编辑器；插件保存场景/脚本，再以项目外配套引擎启动游戏。普通 F5 仍运行原版引擎，无法使用右键原生离线模式；插件不取代 F5，也不会把原版进程冒充为离线录制版。使用、路径和故障提示见 `tools/offline_engine/README.md`。
- 项目根目录 **`启动离线录制版.cmd`**：使用独立 Godot 4.7.2 运行项目。
- **`启动离线版编辑器.cmd`**：可选的独立编辑器入口；不要让两个编辑器同时编辑同一项目。
- Steam 原版及已有进程未覆盖、未关闭。旧进程不能热切换引擎；原版仍支持左键，右键会明确提示换入口，绝不退回重打。
- 源码补丁、SHA-256、构建和使用方法见 `tools/offline_engine/`。二进制在项目外 `E:/godot/polo-balls-tools/offline-engine/runtime/`。

### 当前实现

- 没有序列化重建另一局。原角色、飞行物、生命、位置、速度、脚本执行状态和现存计时器原地继续。
- 固定 60fps 离线时间：一帧完成后才推进下一帧。等待编码不增加游戏/视频时间，不通过重复旧画面填满计算耗时。
- 原生离线混音沿用当前音频流/解码器；视频每帧拉取精确采样数，包含 GameplayRecord，不录 UI。硬件音频不在后台另行推进声音。
- 项目中许多技能依赖 `Time.get_ticks_*`，因此离线时也改为连续虚拟时钟；结束保持绝对冷却时间戳连续。真实编码超时使用 `Time.get_wall_ticks_*`，不受虚拟时钟影响。
- 用户基础倍速临时规范为 1x，技能自身的时间覆写保留；结束恢复用户倍速。窗口不再重画第三套战场，只低频显示已有录制帧作为进度背景，最小化仍生成离屏帧；取消、暂停、场景退出有清理路径。
- 中英文仍共享一次计算与同一音频；现行命名使用各语言的角色名和各自数量格式，不加Mc小球前缀，见本文顶部最新规则。
- 这不是只计算一个胜负数字。完整高质量视频必须绘制各帧，耗时取决于人物/特效、GPU 读回与双路编码，**不承诺比实时更快**；但不再固定花四倍时间，也不把慢计算导出成慢动作。无终局时可中止保存片段。

## 两种模式共同保留的规则

- 原生 **1080×1920 / 60fps**，仅对战画面和 GameplayRecord 游戏音轨；排除鼠标、工具栏、暂停和恢复倒计时 UI 及其 UI 声音。保留主窗口 HDR/sRGB 转换和常驻暗角；半透明效果不因错误 Alpha 处理而变暗。
- 暂停、布阵等待不计入成片；录制中或收尾时不能修改目录。设置 → 录制可选择并持久记忆目录，支持中文/空格并校验可写性。默认 `user://recordings`。面板仅保留「打开」（打开保存文件夹）和「设置」（选择路径）两个按钮，手输路径按回车即保存。
- 每次同一世界、同一时间线输出两份有声 MP4，不分别打两场。两路视口各自替换可翻译的文字；共享同一份游戏音频。
- 现行文件名如 `3个钻石剑 vs 2个木剑.mp4` / `Diamond Sword ＊ 3 vs Wooden Sword ＊ 2.mp4`，无语言/模式/时间戳；同队同名合并计数，单个不写数量，随机来源保留，重名与已有中间文件避让编号。录制开始时固定命名信息，不随角色死亡改名；内嵌标题的角色名冒号/数量星号保留半角。
- 优先硬件 H.264，必要时使用软件编码。编码线程有内存上限。LIVE 保留实时行为和过载错误提示，不因右键方案改成固定帧；离线则在队列满时等待，不跳过物理帧。
- 真正导出完整过程必须计算和渲染所有帧；视频正常速度不等于保证计算速度超过实时。
