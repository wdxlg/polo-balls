# 新版凋零预览与直接旋转开场（2026-09-24）

> 本文记录 9 月 24 日的实现和测试基线。其中“110 半径”是历史数值；9 月 25 日觉醒爆炸半径已缩至 72，射击/玫瑰更新与现行回归见 `tests/WITHER_CADENCE_TUNING.md`。

## 用户约定

- 选角预览要显示当前新版凋零，而不是旧版正面贴图。
- 删除开场放灵魂沙/骷髅方块的过程，直接进入旋转。
- 用户明确选择旋转 **3 秒**。

## 实现

### 选角、肖像和放置预览

`World.create_character_preview()` 和 `create_ghost_ball()` 会实例化角色，但不把角色放进场景树，所以不会执行 `_ready()`，也不会创建战斗用的 3D 视口。旧 `get_preview_texture()` 因此一直回退到 `wither_front.png`。

本轮增加 `bedrock/wither_preview.png`：通过 `tools/minecraft/bake_wither_preview.gd`，从**战斗中实际使用的同一套六骨骼 Bedrock 模型、原版纹理和相机**渲染一张透明 PNG。不是 AI 重画，也不是继续使用旧正面图。

- 预览为 384×384、最近邻采样、正交相机 size=5.2 / position=(0,2,-6)，与正式角色一致。
- 保留完整视口画布，不裁剪后随意放大；场景预置图像缩放为 `0.425*5.2/4.3≈0.51395349`，与正式模型的世界尺寸一致。
- 场景的 Image 默认纹理及离树时 `get_preview_texture()` 均使用新预览；正式角色进树后仍用原来的实时 3D 模型，不把战斗动画替换成静态图。
- 菜单预览只复制轻量视觉节点，不会触发开场、音效、AI、伤害或创建额外实时 3D 视口。
- 烘焙信息和来源哈希：`Images/characters/我的世界/wither/bedrock/PREVIEW_MANIFEST.json`。原版资源来源仍沿用同目录 `SOURCE_MANIFEST.json`。
- 没有改动 World 或 UI 的公共预览逻辑；已有角色不受影响。正在运行的旧进程仍可能持有旧预览缓存，需重新运行项目刷新。

### 开场直接旋转

- 删除 `_draw()` 中按时间放置灵魂沙/骷髅的绘制逻辑，以及专用方块矩形函数和相关常量。历史素材文件不强行删除，避免影响资源归档或其他引用。
- `_ready()` 即显示新版实时凋零，初始用原有蓝色免伤阶段纹理；t=0 不再隐藏模型，也不再等到总进度 80% 才显示。
- 骨架旋转改为 `TAU * 2 * intro_progress`，**整个 3 秒都在旋转，共两圈**。旧版只在最后约 0.6 秒旋转两圈；本轮让旋转阶段完整持续 3 秒。
- 初始膨胀取原先旋转阶段的尺度范围，避免把被删除的构筑阶段的大幅膨胀误带进来、导致模型裁切。
- 3 秒结束正常觉醒：恢复普通皮肤、正面朝向，触发一次既有的 110 半径 / 45 基础伤害觉醒爆炸及原音效。时间边界增加极小浮点容差，避免 30fps 累加误差多等一帧。
- 旋转期原有免伤、投射物反射和末 0.4 秒的真实爆炸威胁提示保留；暂停不推进旋转。未改骷髅射击、玫瑰、冲撞、半血护甲或信标。
- 仍沿用原外观同步字段和接口；专项检查接收相位 0 / 0.5 的显示与旋转映射。**没有进行真实双客户端整场同步验证**，不把接收函数检查称为联机验收。

### GPU 图像对照与预览视频

- 使用新版代码下的实际战斗视口，设置与预览相同的标准姿态，保存 `live_reference.png`。
- 与新的菜单 PNG 比较全部 RGBA 像素：**不同像素数 0，逐像素一致**。
- 保存 `user://wither_intro/` 下 **150 帧、384×512、30fps、5 秒**实机渲染预览：前 1 秒是实际选角预览节点，接着完整 3 秒旋转和 1 秒觉醒画面。画面文字区分 `Selection preview` / `Spawn` / `Awake`，前 1 秒不是额外开场等待。
- 已查看第 0 / 34 / 52 / 95 帧，确认新版外观、不同旋转角度、无方块搭建；视频静音且仅在夹具隐藏血条，不修改游戏声音与血条。
