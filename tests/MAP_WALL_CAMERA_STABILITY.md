# 3D 墙体镜头稳定性（2026-09-26）

## 问题与修复

用户反馈：墙有时抖动，尤其是不断改变视角时。真实 D3D12 回归复现了两条独立原因：

1. 项目启用 `snap_2d_transforms_to_pixel`。旧墙体 Sprite 用逆 Camera2D 变换把已渲染的 3D 纹理放回世界，逆变换平移被取整后又经过镜头 zoom 放大；其它地图几何并没有同样的逆变换，导致墙相对地图跳动。
2. 旧投影更新发生在普通 `_process()`；后执行的相机逻辑可以再次改变画布，墙的 3D 相机未同步最终画布。墙还调用 `force_update_scroll()`，视觉系统本不应额外推进相机平滑。

修复仅涉及墙渲染器与合成 shader，不修改世界镜头控制、全局像素吸附或人物运动：

- 新 `shaders/map_wall_composite.gdshader` 使用 `skip_vertex_transform`，只对墙与地影两张合成 Sprite 传入未取整的精确世界变换，绕过它们的模型平移取整；保留原 UV 和纹理最近邻采样。**不是关掉整个项目的 pixel snap，也不是把世界画面磨糊。**
- 不使用 `SCREEN_UV` 固定取样，避免不同缩放的共享 World2D 录制/总览视口把墙锁在错误的屏幕位置。
- 在 `RenderingServer.frame_pre_draw` 读取最终 Camera2D 画布，统一更新两路 Camera3D、Sprite 与 shader 变换；不再从墙里调用 `force_update_scroll()`。暂停时仍可跟随工具栏平移/缩放。
- 退出树时明确断开绘制回调并停止两路 SubViewport；蓝色地图停更逻辑不变。镜头变化不重建 ArrayMesh。
- 0.4 格墙高、相邻方块无缝、短影、原版材质、真实透视视差、门洞、原碰撞、昼夜顺时针太阳与亮度均保留。正常的游戏镜头震动并没有被禁用。

## 实际验证

Godot 4.7.2 / Windows / D3D12 / RTX 4060 Laptop。每项检查实际进程退出码。

| 测试 | 结果 | 范围 |
| --- | --- | --- |
