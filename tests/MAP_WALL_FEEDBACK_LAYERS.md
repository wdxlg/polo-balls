# 墙与战斗反馈绘制层级（2026-09-26）

> 后续修正：本篇记录的墙 Z=90 方案遗漏了 Z=-3 的药水/附魔框。现行实现已改为墙 Z=-4、先进入背景快照，且非蓝色主题不再叠加外黑框；以下表格/顺序仅为历史记录。当前规则与新增真实信息框 GPU 回归见 `MAP_WALL_TOOLTIPS_AND_BORDER.md`。

## 问题与约定

原 3D 墙是绝对 Z=99，地影继承父层 -1 后实际为 98；伤害跳字为绝对 98，血条默认绝对 99，因此文字被墙盖住，血条还受创建顺序影响。项目也有 91、92 层的技能反馈，不能仅把墙降到 92。

当前绘制顺序：

| 内容 | 世界画布 Z / 顺序 |
| --- | --- |
| 地图地面 | -5（原值） |
| 3D 地影 | **绝对 -4**，不再继承墙的前景层 |
| 状态框 / 普通世界对象 | 维持原有层级 |
| 地图外遮罩 | 90（原值） |
| 3D 墙 | **绝对 90，场景树顺序在 MapOutsideVisualMask 后** |
| 战斗反馈 / 跳字 / 血条 | 91–99（保留原值，跳字 98、血条默认 99） |
| 边框 / 门扇 | 100（原值） |

`地图立体墙.gd::configure_regions()` 每次地图/主题刷新检查同父节点下的绘制顺序；若墙排到遮罩前，移到遮罩后。不要简单降到 89 或以下，否则墙的地图外侧会被遮罩擦掉。独立无地图遮罩的 GPU 夹具仍可使用该组件。

仅修改墙组件的层级/同层顺序，不修改 World、公共伤害跳字、血条或技能脚本。0.4 格低墙、无缝网格、原版贴图、短影、昼夜、碰撞与门洞、精确坐标合成和最终帧相机同步均保留。

## 本次验证

Godot 4.7.2，Windows D3D12 Forward+，RTX 4060 Laptop。新夹具 `tests/test_map_wall_feedback_layers.gd` 加载真实 `world.tscn`、`damage_text.tscn`、`health_bar.tscn`，五种方块主题逐一 GPU 读回；反馈在墙创建之前入树，覆盖同 Z 顺序问题。

- 修复前原始 75 项夹具：**65 项失败，实际 Godot 子进程 exit 1**；修复后同夹具 **75/75，exit 0**。
- 最终夹具额外包含五主题的“人为颠倒遮罩/墙顺序再刷新”：**80/80，exit 0**。
- 真实数字/血条相对正确分层参考图的差异像素均为 **0**；恢复旧墙 99/地影 98 的负对照后，数字区域分别有 **695 / 710 / 678 / 638 / 691** 像素改变，血条区域各 **954** 像素改变（grass / sand / stone / nether / end，RGB 差阈值 0.045）。不是只比较节点属性。
- 第 91–99 层逐层色块探针均可覆盖墙；地影不再压暗 Z=1 的世界对象；地图外遮罩仍裁掉越界前景，而墙外侧仍有可见像素。
- 同次回归：相机稳定性 **10/10**，真实墙/地影/门洞 GPU **49/49**，昼夜 GPU **39/39**，墙结构/碰撞在 D3D12 下 **111/111**，这四次实际 Godot 子进程均 exit 0。相机静态/运动/共享视口采样的 alpha 差异与质心偏移仍为 0。
- headless 结构测试两次均完成 111 项断言、0 断言失败，但进程退出为 **3221225477（0xC0000005）**，不能算测试成功；保留两次日志，不通过修改断言或吞掉退出码掩盖问题。另用仅在进程内接管资源路径、持有墙脚本引用的检查点包装器对照：旧/新墙脚本均完成 **111/111、exit 0**（`baseline_shutdown_probe` / `current_shutdown_probe`）；包装器不是标准运行入口，且退出阶段仍有异步资源预载报错，因此不能据此宣布直接 headless 退出问题已修好或已确定根因。
- 修改的三份 GDScript 诊断无错误/警告；实际查看了修复后及旧层负对照的 GPU 截图。

边界：血条由夹具提供最小健康属性 owner；数字使用真实场景和金额样式但冻结飞行动画，91–99 层使用合成探针，不等同于逐一游玩全部技能。未做双客户端联机、长时间性能或编码视频端到端验收。项目既有 shader UID/大小写警告、退出 ObjectDB 泄漏警告及 headless MCnew5 资源预载问题不在本更新范围，不能据此宣称全项目零错误。
