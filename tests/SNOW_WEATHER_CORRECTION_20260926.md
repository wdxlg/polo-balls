# 雪环境：空白开局、原版 3D 墙雪与飘雪纠正

## 要求及改动

用户纠正：雪一开始不存在；墙上是一个 3D 的 Minecraft 雪片，不是涂白；应有 Minecraft 下雪特效。

1. 删除 `_seed_initial` 及其延迟回调，不再预放 8 地面 + 4 墙面雪。新局、布阵、换图、重置/重打、重新启用均空白。运行后天气渐入，满 2 战斗秒开始积雪，后续仍每 0.45 秒尝试一片；晚加入保留房主已有积雪。
2. 旧墙面二维 `draw_texture_rect_region` 被真正的 `ArrayMesh` 雪层替代：原版 `snow_height2` 的 2/16 厚度及侧 UV，原版雪方块纹理。底面贴墙顶，具有顶面、垂直侧面、真实深度及光照。六个方块背景直接共用墙的 World3D、相机、太阳/环境；蓝色仍是原平面边框，只为雪片复用同一 3D 渲染实现。
3. 原版 64×256 天气降雪贴图三层移动，运行时渐入；使用世界坐标、战斗 delta 和独立随机相位。暂停冻结，关闭立即清除，各端本地播放，不发伤害 RPC。只用三次纹理绘制，没有每雪花一个节点/计时器。
4. `地图立体墙.gd` 增加可复用的 `append_world_cuboid` 与蓝色装饰通道入口；普通墙委托给原来的尺寸、UV 和高度，其他相机/灯光/背景/云的并行改动未被替换。地板专用通道的阴影代理是可选能力，不强依赖并行新增的层常量。
5. 保留原雪地接触、寒冷伤害/免疫/状态、雪傀儡造人和普通雪径融化；墙雪和天气无伤害/积寒/控制。**雪球直击仍是普通伤害且保留击退。**

原资源、版本、来源及 SHA-256：`Images/effects/我的世界/雪环境/SOURCE.json`。素材未重绘、未生成、未修改原像素；不宣称原版游戏素材可自由再分发。

### GPU 实证

- 每种背景检查真实 mesh、非零厚度（CELL=24 时厚 3）、底部等于实际墙顶、原版材质及关闭自发光。方块主题还检查其 parent 与 renderer 就是现有墙通道。
- 像素取点按真实 3D 相机投影，不再在旧二维裁切矩形上凑白色像素；垂直侧面与顶面使用实际亮度比较。
- 开始时 field 积雪为空、无雪 mesh；第一秒仅飘雪，没有任何积雪。原版天气在 OpenGL 整幅画面产生 7479 个显著变化像素；不同时间图像变化、暂停图像稳定。
- `*_snow_and_golem.png` 是刻意排列的近景几何夹具，不冒充随机分布。`random_weather_production.png` 使用真实生成器推进 40.8 秒，不注入地面/墙雪。
- onset 序列是 49 张实际 OpenGL 帧，0→4.8 战斗秒：先空白，再飘雪，随后自然出现积雪。预览按 10fps 合成为 4.9 秒 MP4；它是验证预览，**不是正式 BattleRecorder 双语编码链路验收**。
- 共享 World2D 的 620×840 竖屏视口也核验了降雪像素；未进行两台独立机器或正式 1080×1920/60fps 双语成片验收。

### 调试过程与边界（不隐藏失败）

- 首次生命周期夹具在空的手动布阵场推进积雪失败：World 正确拒绝无存活角色的战斗计时。夹具补充真实角色并等待物理帧，未放宽生产暂停/布阵条件。
- 首次侧面断言误用 HSV 的 `v`：蓝光侧面 B=1 不代表亮度与顶面一致。改为亮度比较，并把近景相机移到完整雪层可见处，仍保留侧面可见像素断言。
- 首次共享视口在入树前设置 canvas transform 报错；调整为入树后设置。较长的首次 onset 抓帧达到夹具超时；改为可选独立捕捉模式，完整复跑通过。
- ENet 新夹具曾向 `Array[Rect2]` 属性赋无类型数组，中断后只完成 8 项，不能算联机通过；修正为明确类型的数组后 27 项全部通过。
- 一次回归命令误写音效测试文件名，文件不存在导致该组停下。随后使用实际 `hit_audio`、`projectile_contacts`、`build_revision` 路径执行并通过，不把未运行的条目计入。
- 首次隔离编辑器导入 exit 0，但两个既有编辑器插件读取未初始化的语言设置时报告 String/Nil 错误；不是干净的编辑器全检。资产成功导入、运行时全部相关脚本实际载入且最终测试无 ERROR/FAIL/TIMEOUT。
- 当前多项退出仍有 **156 ObjectDB instances leaked** 告警，原雪傀儡回归中也复现；本轮未定位该退出告警的归因，**不宣称整个项目无警告/无泄漏**。另保留原 `set_rgb_color.gdshader` UID/大小写告警，没有为了让日志变绿改无关资源。
