# 盔甲架介绍录制：终局校验与角色文件名（2026-09-26）

## 用户选择

- 命名用于**保存的视频文件名**，不改变画面里的介绍标题。
- 保留自动停止，但必须在**真正结束对战后**才开始续录收尾；不是固定录几秒，也不是改成只能手动停止。
- 中文 `Mc小球新角色:角色名`；英文只用角色英文名。Windows 文件名将冒号换为全角 `：`，MP4 元数据保留 ASCII 冒号。

## 已复现的提前停止路径

检查点 `baseline-probe.log`：先用真实 World 结算一次普通战斗，然后在同一场景补放不死盔甲架。场上重新有两个存活阵营，`_armor_stand_test_hud_active=true`，但 `_victory_bell_played` 仍保留上一场的 true。原 `_match_over_now()` 无条件接受这个旧标记，SIM 开始续录并提前完成；命名同时沿用旧布阵，变成“烈焰人 vs 木剑 + 不死盔甲架”。

修复后同一探针：两个阵营仍存活、旧铃声仍为 true，录制返回未结束；模拟推进六秒后 `finished=false / tail=-1`。没有清空世界胜负状态来伪造复现结果。

## 实现

### 自动停止

`battle_recorder.gd::_armor_recording_still_contested()` 仅在当前盔甲架介绍或本次录制已保存的盔甲架上下文中，复用 World 的 `_collect_alive_victory_sides()`（含主角色、附属和死亡桥规则）。仍有对立存活阵营时，拒绝旧胜利标记；若之前已启动续录，也取消这一失效倒计时。

- LIVE 与 SIM 共用同一校验，不再只让 LIVE 避开开始时的旧标记。
- **不通过剩余阵营数量擅自推断普通对战终局**；普通录制仍以正式胜利/队列结果为准。
- 计时对战真正到期、轮换队列真正结束仍可正常收尾，即使场上还有存活角色。
- 真正终局后沿用设置中的续录秒数、游戏时间计时、暂停与手动停止，不重置战斗、不缩短内容、不新增时长上限。
- 不死/虚无盔甲架对战若一直没有终局，会持续录制；用户仍能手动停止。

### 文件名

`battle_record_naming.gd::snapshot()` 复用介绍的主角色锁定，保存开始时的角色身份。忽略旧布阵中的已死敌人、盔甲架和普通召唤物；开始之后不因角色死亡、召唤或重新选择而改文件名。

例：

```text
中文：Mc小球新角色：烈焰人.mp4
英文：Blaze.mp4
```

重名使用原有 `(2)` 等序号，不覆盖旧视频；保留非法字符处理、路径预算和截断哈希。中文路径预算相应扩大最低需求，不能截掉“Mc小球新角色：”前缀。普通对战的数量、随机来源与命名格式不变。屏幕标题/介绍文本不改。
