## 受光诊断与修复

真实 D3D12 对照使用同一个材质、相机和灯，比较 Godot `PlaneMesh`、竞技场程序面、低墙程序面：

| 白色对照面的读回 RGB | 修改前 | 修改后 |
| --- | --- | --- |
| Godot 原生面 | 0.4784 / 0.4784 / 0.4784 | 不变 |
| 竞技场面 | 0.4784 / 0.4784 / 0.4784 | 不变 |
| 低墙面 | 0.1961 / 0.1961 / 0.1961 | 0.4784 / 0.4784 / 0.4784 |

竞技场绕序原本正确，**没有反转它**。低墙 `_face()` 的绕序与所提供的外法线不一致；在 `CULL_DISABLED` 下按背面受光。修正为 Godot 的顺时针正面；同一帮助函数创建的旧地图接影平面也获得正确朝向。移除普通墙材质原有的分主题自发光补偿，使用真实方向光和环境光；不是把所有方块变成同一种颜色。

主太阳的 `VisualInstance3D.layers` 必须同时包含前景位 1 与山体位 2。只共用 `World3D` 不够：若灯自身仍只在位 1，山体相机看不到方向光，会只剩环境光。回归分别渲染相同位置/材质的双层对照面，在 12:00、18:00、00:00 三个时刻均得到 `(0.6039, 0.6118, 0.6118)`，两通道 RGB 最大误差 **0**。

昼夜继续使用唯一世界乘色层，不给 3D 增加第二次夜间变暗。`sun_light.shadow_opacity` 随 daylight 淡出，使真实山体/竞技场太阳影子与旧地图独立接影通道一样在夜间淡出；旧接影视口仍只由其合成 alpha 淡出一次。

## 正确的显示顺序

山体和竞技场以前位于同一张不透明 3D 合成图内，Z=-5 的云被 Z=-4 的整幅图遮住。单纯把云抬高会反过来盖住建筑。

现在只对山巅启用两个**显示通道**，并非两个独立场景或两套光照：

| 绝对 Z | 内容 |
| --- | --- |
| -8 | 原始蓝色底图；记住其原 Z/相对属性，切回其他背景精确恢复 |
| -7 | 兜底场外网格 |
| -6 | 主山、后山、共享山脉与谷底地面 |
| -5 | 已确认的原版平铺云；山巅模式连续铺到竞技场下方 |
| -4 | 竞技场地面、低墙、薄台面、观战席与柱子 |
| -3 及以上 | 原信息框、角色、战斗文字等原有层级 |

- 新背景视口使用主视口 **`find_world_3d()`** 返回的实际世界，复用太阳、环境、模型和材质；不误用 `own_world_3d` 下的非实际世界引用。
- 两个 `Camera3D` 在最终绘制前同步变换、投影、FOV、宽高比、near/far、frustum offset、相机环境/曝光及视口尺寸，仅 cull mask 不同。
- 两张合成 Sprite 共用现有精确世界变换 shader；不关闭全局 pixel snap，也不反复推进 Camera2D 平滑。
- 主山、后山、167 座共享模型山脉及谷底只改可见位。竞技场装饰仍留在前景，不靠矩形近似去挡柱子或门洞。
- 切离山巅停用背景视口并隐藏其图片；重复切换复用同一个视口。原始底图的深度必须一同调整，否则它继承 World 的 Z 后仍会盖住山体。

云仍是用户确认的平铺 32×32 方格、向下 32/3 厚边、实心白顶/0.70 下沿；**未改 Shader、原 PNG、角度、厚度、速度或视差**。蓝色仍是上空云，五种旧方块背景仍用多岛场外补集。只有山巅依靠真实前景 alpha 遮挡连续云层；共享 World2D、暂停、保存/重载和重置语义不变。
