# 石头：真正的静态障碍物

## 当前行为

- `scenes/characters/默认/石头.tscn` 现为独立的 **StaticBody2D**，不再继承 `ball.tscn`；脚本也不再 `extends ball`。
- 只有图像、实体碰撞和静态放置同步。没有队伍、生命/攻击/移动属性、角色状态机、血条或 Hitbox/Hurtbox；不进入 `Ball` 组或战斗单位缓存。
- 仅占地形层1，碰撞掩码2。人物、地形射线与铁砧按真正的障碍处理；角色碰撞优化关闭实体互撞时仍不能穿过石头。石头自身不能被推挤或角色击退。
- 保留原图、世界碰撞尺寸23×25.5及图像世界缩放0.025。沿用原先的不可伤害属性，但改用已有的地形保护标记 `ghast_indestructible`，不是伪装角色血量或覆盖伤害函数；仍可主动右键删除。
- 铁砧跳跃碰到真实石头会在接触处立即下砸；砸到石头顶部按地形落地，并阻挡对石头下方敌人的伤害。天堂陨落长弓仍按其既定规则消耗一次障碍穿透并生成裂隙，石头不是伤害目标。

## 放置、战斗与兼容

- 保留原资源路径和默认分类的手动放置入口，避免旧布局或引用失效；搜索仍能找到石头，按钮提示明确标注“障碍物”。路径位于旧角色目录不代表运行时仍是角色。
- `World.PLACEABLE_OBSTACLE_SCENES` 独立登记障碍物，不需要为分类判断预加载全部角色资源。
- `return_all_character_names()`、普通随机选角和随机布阵池排除石头。手动搜索使用 `return_all_placement_names()`。
- 放置预览只复制视觉，不生成碰撞/角色实例；石头走独立的中立地形创建流程，不占轮放席位、计时伤害名单或Boss强化，也不贡献角色数量或胜负阵营。
- 保持 `_find_ball_ancestor()` 只识别角色；右键删除另用 `_find_deletable_ancestor()` 识别明确标记的可放置静态地形，不把普通地图边界变成可删对象。
- 布局条目记录 `kind: obstacle`、空队伍和初始位置。清空、重开、重开已清空的场地均支持石头；旧版没有kind字段的石头布局也重建为静态地形。删除障碍物会移除布局条目，但不重置战斗胜利状态。
- 场景的 `MultiplayerSynchronizer` 使用放置位置、旋转、缩放的spawn/on-change同步；不引入角色属性同步。未运行真实双客户端网络会话。

## 手工复核

1. 从原默认入口放置石头，或搜索“石头”；应显示障碍物提示且无血条。
2. 放置普通角色或铁砧，确认身体被石头挡住；铁砧跳中碰石头立即下砸。
3. 右键删除石头，再重开，已删除的石头不应回归。
4. 保留石头并重开/先清空再重开，石头应回到初始摆放位置。
5. 随机布阵、轮放、计时或Boss模式中，石头不作为出战人物或计分对象。
