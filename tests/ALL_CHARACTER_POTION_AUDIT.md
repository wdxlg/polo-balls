# 全角色药水效果核查（2026-09-25）

## 结论先行

**不能说“所有角色、所有衍生攻击都遵循了药水效果”。** 通用的状态施加、属性 Buff 和多数标准受击路径可用，但自定义技能未必读取这些属性。已复现女巫炼药不随急迫变快，以及苦力怕的爆炸不随力量增强。决斗者的两处明确受击漏接已在本次修复；其余涉及既有角色设计、`Damage=0` 或独立召唤物归属的改动不擅自做全局平衡调整。

## 实际测了什么

- `tests/test_all_character_potion_contract.gd -- --tracked-only`：遍历 **132 个 Git 跟踪的角色场景 + 17 个跟踪的随从/衍生物场景**；其中 145 个是可走 `World.figure_buffs()` 的 Ball/Creature，另 4 个是非球形实体（军火商的枪、火车长列车、猎人捕兽夹、领导房产业主）。**3338 项检查、0 失败**（最终一次运行结果以测试控制台输出为准）。逐场实例化后施加二级迅捷、急迫、力量、抗性、生命提升、伤害吸收、防火、缓慢、挖掘疲劳、虚弱；实际计算 `Speed`、`Attack_Cooling`、`Damage`、`Damage_reduction`、`Max_health`，并检查临时生命与防火拒伤。不是只查图标。所有被测战斗单位允许正、负药水效果（无整类免疫）。
- 同一个测试在未加 `--tracked-only` 时遍历**工作区内 182 场景**：177 个可实例化战斗单位的属性断言通过，5 个非球形实体跳过；**但**另一个会话尚未纳入 Git 的 `scripts/characters/我的世界/蜘蛛.gd` 当前有 `setup()` 传 6 个参数而目标只收 5 个的 GDScript 解析/依赖编译错误。Godot 仍能实例化其继承的基础场景并执行属性断言，因此这一次不能算“182 个完整角色全部运行正常”；该工作中资源须由所属任务修复后复测。此错误不属于本次药水修复。
- `tests/test_duelist_potion_defense.gd`：修复前 **9 项中 3 项失败**，修复后 **9/9**；检验弱点原始伤害先扣吸收、剩余部分才扣真实血量，以及水下呼吸对 `element=drowning` 拒伤而不误免疫普通原始伤害。
- 已有专题回归：`test_mc_unified_status_effects.gd` **137/137**，`test_mc_potion_phasing.gd` **17/17**，`test_wither_beacon_revision.gd` **49/49**。它们验证效果目录、持续/瞬间伤害、隐身碰撞、缓降、渗浆资源条件、凋灵本体/信标边界等代表性链路；不是“所有特殊技能”的逐招测试。
- 对已跟踪的 **169 个角色脚本、31 个 shooter 脚本**，以及随从、效果脚本做调用链静态筛查；例如建筑工人的砖块本身虽然直接使用 `enemy_damage`，但创建处已由施法者 `attack_damage(brick_enemy_damage_multiplier)` 写入，**不能误报为漏接**。静态扫描候选也不能代替逐招运行验证。

## 修复：决斗者的自定义受击覆写

`scripts/characters/决斗者.gd` 的弱点判定会绕过 `ball.receive_spatial_damage()`：

1. 命中弱点的 `raw_health=true` 分支之前直接 `health -= damage`，使**伤害吸收**的临时生命完全失效；现在与基类一致，先 `_consume_minecraft_absorption()` 再扣真正溢出的伤害。原始伤害**仍故意绕过抗性/格挡**，未改变角色弱点许可或基础数值。
2. 带 `{"element":"drowning"}` 的空间伤害之前没有检查**水下呼吸／潮涌能量**；现在在弱点计算前沿用基类相同的标签拒伤，只免溺水，不免普通水属性攻击。项目没有主动氧气耗尽伤害源，不能据此声称整套水下生存机制已实现。

## 明确未全面生效：实战反例及待决策事项

| 场景 / 状态 | 动态复现或源码追踪 | 为什么这次没有强改 |
|---|---|---|
| 女巫：急迫／挖掘疲劳 | 真实场景中急迫 II 将 `Attack_Cooling` 从 **1.0 降到 0.80645**；手动推进 0.2 秒后，炼药等待计时 `_brew_left` 在无/有急迫时均从 1.0 到 **0.8**。`女巫.gd:116,369–372` 直接以 `delta` 递减，且明确注释“固定冷却，不再受 Attack_Cooling / 速度药水二次缩放”。| 这是已有**有意固定炼药频率**的设计，不是单纯漏写一行；改变它会触及施法节奏，先请用户决定急迫是否应打破该例外。这里的“速度药水”是迅捷，不能错误地把迅捷当急迫。 |
| 苦力怕：力量／虚弱 | 二级力量已成功安装，但场景基础 `Damage=0`，Buff 后依然 **0**；普通爆炸对 3000 HP 测试目标在加药前后均造成 **500 HP**。`苦力怕.gd:552` 使用独立的 `explosion_damage`，雷电也使用 `lightning_damage`。 | 直接把场景 `Damage` 从 0 改成 500，或全面规定独立爆炸应继承本体属性，超出“不改基础数值的安全漏接”；应先确定自爆/闪电是否按本体攻击倍率缩放，之后再设计不改变原始 500/38 的计算方式。 |
| 女巫：药水瓶**实体撞击**的力量／虚弱 | `scripts/effects/我的世界/女巫药水.gd:93` 向目标传固定 **50** 点，未读取施法女巫实时 `Damage`；其药水状态本身的周期/瞬间效果应保持独立，不应连带缩放。 | 对撞击的归属与倍率（女巫基础 `Damage=20`、瓶身基准 50）应单独接入；此投射物脚本已有另一项未提交改动，本次没有覆盖、暂存或捎带提交他人内容。 |
| Sans：重力砸墙伤害 | `Sans.gd:2138–2141` 由目标的撞击速度单独算出伤害，未直接读取 Sans 实时 `Damage`；**这是源码疑点而非本次动态复现的失败**。 | 环境速度伤害是否应吃力量需要设计约定；没有把所有速度、比例和百分比伤害无条件乘本体力量。 |

以上反例说明“角色能拿到属性 Buff”≠“每个攻击/技能都消费该属性”。其他有私有计时器、位移、碰撞或独立弹丸的技能仍需要按攻击归属逐招定义；本轮不把静态可疑数当成已证实的失败数，也不声称已运行每一招。

## 39 种目录的玩法边界

- **已有可执行机制（含有条件的部分实现）：** 迅捷、缓慢、急迫、挖掘疲劳、力量、虚弱、抗性提升、生命提升、伤害吸收、瞬间治疗、瞬间伤害、生命恢复、中毒、凋零、隐身、飘浮、防火、水下呼吸、潮涌能量、缓降、虫蚀、渗浆、盘丝、蓄风，共 **24** 种。**不要把“目录已实现”误解为所有技能都生效：**水下呼吸/潮涌能量目前只响应显式溺水标签，场上无通用氧气/主动溺水源；缓降只作用于有下降 `velocity` 的单位；渗浆依赖额外的小史莱姆资源，独立检出本提交未必具备。
- **仅目录/等级说明，缺少对应游戏系统或公共接入点（15 种）：** 跳跃提升、失明、黑暗、夜视、反胃、发光、海豚的恩惠、幸运、霉运、饥饿、饱和、不祥之兆、袭击之兆、试炼之兆、村庄英雄。可安装状态/显示图标**不代表原版玩法生效**；即使个别角色能跳跃，目前也没有供药水统一调用的跳跃入口。
- 边界特例：用户指定凋灵本体头颅/冲撞/觉醒爆炸吃实时 `Damage`；信标光柱和玫瑰是独立攻击，不随凋灵力量叠乘。凋零 DoT 按受击者最大生命结算，不按施法者攻击力叠乘。原始伤害有意无视抗性，但不该无视临时吸收值。
