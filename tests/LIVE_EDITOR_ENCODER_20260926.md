# 编辑器左键录制持续缓存溢出：滤镜线程修复（2026-09-26）

## 实际失败与复现路径

用户在上一轮更新后再次提供134帧报错截图，并明确“正常的编辑器左键录制，谁vs谁都会编码错误”。本轮原日志还包含盔甲架153帧中断，均为有界写入队列溢出。不是某个角色的胜负逻辑，也不是100秒尾录设置导致停止。

上一轮GPU准备阶段修复保留，但独立CLI/SceneTree测试不能替代编辑器运行。此次先做同机、同Steam引擎、D3D12、相同D盘目录、正常音频驱动的独立/控制器测试，仍能正常录制；随后通过**现有Steam编辑器F6启动、实际嵌入游戏窗口、调试连接及录制按钮入口**复现。

- 环境：Godot `4.7.2.stable.steam.ed1daf0bf`，D3D12 Forward+，RTX4060 Laptop。
- 实际编辑器启动参数含 `--remote-debug tcp://127.0.0.1:6007 --editor-pid … --scene res://scenes/world.tscn --wid …`。
- 基线：输入按60fps持续入队，两个NVENC写入端稳定区间仅约40–50fps，队列持续增长；99内部帧时以与用户相同的缓存满错误停止。该数是记录器内部计数，不宣称异常片实际保留相同帧数。
- 单变量候选：只给FFmpeg增加 `-filter_threads 2`，同编辑器路径1143帧/19.053秒正常，稳定期间队列基本清空。

## 最小运行代码改动

仅 `scripts/ui/battle_recorder.gd` 新增 `ENCODER_FILTER_THREADS=2` 与对应FFmpeg参数（含解释注释，共4行）。NVENC使用GPU编码，但RGBA→YUV/颜色矩阵滤镜仍消耗CPU；中英文两个自动按CPU核数扩张的滤镜池在编辑器负载下争抢，限制每个进程的滤镜并发后可以跟上60fps输入。滤镜线程与软件编码器原有 `-threads 2` 是不同设置。

不改1080×1920/60fps、NVENC p4/constqp16、软件CRF、颜色矩阵或音频；不扩大256MiB/120帧上限、不吞帧、不阻塞主线程等编码器、不减慢游戏、不关闭过载保护。首帧准备、真实终局/尾录、盔甲架名称及旧胜利铃保护保留。公共编码入口也覆盖SIM，已回归。
