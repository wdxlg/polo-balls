# 信标外观、移动与光柱周期（2026-09-24）

## 本次约定

信标仍由凋零半血召唤，有独立 180 生命、真实重力和碰撞，不加入单独选角列表。最新用户明确增强：正式发射 5 秒、每 0.1 秒 6 点，基础整轮 300；正式发射瞬间添加从信标顶部平面扩散的伪 3D 蓝圈。此要求覆盖上一版保持整轮 36 的约定。

## 外观

旧 `beacon_front.png` 只有扁平发光核心，缺少原版玻璃壳与黑曜石底座。本版从官方 Minecraft Java 1.21.11 客户端提取原版 `models/block/beacon.json` 和 glass / obsidian / beacon 三种材质，按原模型三层结构和各面 UV 离线渲染。运行时使用清晰最近邻采样的 `beacon_block/beacon_block.png`，不增加每只信标一个 3D 视口的持续开销。

- 原版模型、材质、官方客户端 URL / SHA-1 和资源 SHA-256：`Images/characters/我的世界/wither/beacon_block/SOURCE_MANIFEST.json`。
- 再生成入口：`tools/minecraft/bake_beacon_block.gd`，需带 GPU 的 Godot `--script` 运行；产物为透明背景 196×208 PNG。
- 角色局部宽度仍为 62；碰撞体高度改为 66，匹配完整方块图像的实际纵横比。未改召唤者、阵营或生命。

## 共用的游戏时间曲线

`beacon_profile.gd` 同时驱动速度、视觉亮芯宽度、实际矩形伤害范围和威胁显示，不能只让图像变宽而伤害仍固定宽度。

1. **预备 0.6 秒**：先出现细发光射线；精灵的位移/小角度颤抖逐渐加强。只抖图像，不抖真实碰撞体或激光方向。主动横向速度用平滑曲线由 100% 降到 50%。
2. **发射 5 秒**：继续移动，不强制停住。前约 0.08 秒快速扩至信标宽度的 116%，随后阻尼弹性回落到约 90%。光柱固定向上，随信标平移，使用原版光柱贴图纵向滚动。
3. **最后 0.35 秒**：亮芯渐细、透明度渐低直至归零，同时速度由 50% 平滑回到 100%。淡淡外光晕只是视觉，不扩大伤害区域。
4. 10 秒周期间隔、每轮结束给凋零一次随机增益、死亡清除增益的机制保留。重力贯穿所有阶段，真实墙面与顶板截断继续生效。

### 高频伤害与整数结算

- 每 **0.1 秒**一次，每次 **6 点**；发射期采样 `0.05, 0.15, …, 4.95`，共 **50 次**，基础整轮 **300**。
- 每次直接传整数 6，继续走既有 MC 有效伤害与音效入口；删除旧 2/3 整数预算分配，未降低原基础音量或新增重复声音。
- 300 指无伤害修正、始终命中的基础值；增益、防御、格挡和途中离开光柱仍参与结算。
- 慢帧在物理步、阶段边界和伤害时间点处分段；不是只在长帧末尾的最终位置补打一串伤害。伤害矩形与敌人的实际启用 hurtbox Shape2D 做相交检查，不再用估计圆半径。
- 动画使用游戏时间。暂停不会继续颤抖或滚动纹理；客户端可插值阶段，但本次未做双客户端联机验证。

## 发射瞬间的蓝色顶部扩散圈

- `beacon_ring.gd` 复用重锤 `pixel_arc.gd` 三层像素环，以及 0.46 秒寿命、3.1 次方扩散缓动、1.28 次方透明衰减；颜色改为蓝/青蓝，不复制地面碎屑、伤害或声音。
- 只在正式发射开始出现一次，不在预备或每个伤害跳重复。以发射阶段的游戏时间为年龄，暂停不会自行扩散。
- 整圈和线宽共同沿 Y 压扁：Y/X = `1.6 / sqrt(2²+1.6²+3²)`，约 0.406，对齐原版方块烘焙相机的顶部平面；不是正对屏幕的圆。
- 后半圈暗一些且在光柱后绘制，前半圈在光柱前；从玻璃顶面中心发出，统一光柱/威胁/圆环起点到贴图 UV `(0.5, 0.196)`，而非贴图最高角。
- 半径由局部 24 扩到 110，统一乘身体世界宽/64，随移动中的信标顶部走。圈本身是纯视觉 Node2D，无伤害与威胁登记；死亡隐藏、父节点删除时随之删除。
- 信标伤害遍历增加已释放候选项的有效性检查，防止目标缓存中的无效引用中断一次伤害事件。
