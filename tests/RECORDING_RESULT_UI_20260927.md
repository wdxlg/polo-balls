# 录制结束大弹窗与无品牌前缀命名（2026-09-27）

## 用户要求与实现

- 录屏结束提示整体太小：不只改一行字体。默认1080×1920逻辑画布在540×960实际窗口中缩小到一半，旧弹窗又用物理窗口宽度当逻辑尺寸。现在通过父视口真实伸缩变换计算物理字号/按钮/边距和弹窗大小，并显式在嵌入视口中定尺寸、居中，避免 `popup_centered` 把桌面物理边界误用于逻辑尺寸。
- 默认540×960窗口下，弹窗主体约508×560实际像素，正文24px、路径18px、按钮22px/至少48px高；更窄的窗口正文仍为20px。包括标题、正文、路径、按钮、间距和滚动条，不改变其他游戏UI。
- 长错误/小窗口使用正文滚动区，确认和打开文件夹固定在底部；滚动条使用主题最小宽度，不遮住文字。AcceptDialog会重设按钮最小尺寸，因此使用其 `buttons_min_height` 主题常量。正文增加行距，路径提高对比度，仍是原始只读LineEdit，可选中复制，不受“Go”等角色名称翻译污染。
- 保留成功、部分录像、失败、PNG/独立音频提示；无英文输出时隐藏空的英文路径。暂停中鼠标/键盘仍能确认；调整窗口后重新适配，已关闭的弹窗不会被延迟resize重新打开。
- 新录像和内嵌标题删除 `Mc小球:`、`Mc小球新角色:` 品牌前缀。普通中文如 `3个钻石剑 vs 2个木剑.mp4`；盔甲架如 `烈焰人.mp4`，英文仍为对应译名（如 `Blaze.mp4`）。不修改画面里的角色介绍标题，不重命名/删除已有录像。
- 冻结初始阵容、数量/随机来源、双语、Unicode安全字符、Windows设备名保护、重名编号、长路径哈希截断及中间文件占位避让均保留。去掉前缀后，中英文共同使用12字符的最低角色名/身份哈希预算。
- 生产改动仅 `scripts/ui/battle_record_controls.gd` 与 `scripts/ui/battle_record_naming.gd`；没有修改录制器、编码器、战斗、音频、真实终局或续录时间。
