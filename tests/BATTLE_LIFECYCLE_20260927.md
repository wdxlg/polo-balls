# 多实体角色过早结算修复 — 2026-09-27

## 结论

已将结束铃声、轮换换人统一到“原参战角色及其仍存活/已确认待生成的后代”判定，不再以原本体节点退出作为整位选手淘汰。没有改变角色的伤害、生命、召唤数量、死亡分裂、复活或原三种轮换玩法。

### 找到的共性问题

1. 普通召唤物的阵营归属依赖胜负轮询碰巧访问并缓存；本体先死、还没轮询的后代可能被漏掉。
2. 轮换的 `tree_exiting` 回调直接将本体槽清空并换人；已有 continuation/death bridge 没有统一接入轮换。
3. 没有 Master 的同批成员/分裂身体（保安、兔子、木剑）只继承 Team，没有原轮换槽身份。
4. 确认后的保安增援、蠹虫延迟孵化可以处于“本体已删除、新身体还没出现”的空档。
5. 药水产生新身体时，施法者已不存在的回退分支只复制目标 Team，没有复制目标存续身份。
6. 原蠹虫兜底曾可以跳过常规模式限制或凭空武装铃声。现在仅通知统一复核，不能另开结算通道。
7. 仅有后代时的战斗运行门槛、1v1整组胜者清场必须同步修复，否则会出现后代停战或旧成员进入下一局。

## 实现与接入规则

入口与范例见 `docs/BATTLE_LIFECYCLE.md`；MCP_CONTEXT.md新增强制规则。

- `World.bind_battle_lifecycle`：公共入树注册与 Master 名称补解析接入，保存原 setup、阵营与有效代次。
- 同一 `_battle_unit_keeps_family_alive` / `_battle_family_alive` 供铃声与队列使用，检查整个角色组。
- `begin_battle_spawn / apply_battle_spawn_identity / finish_battle_spawn`：管理已确认的延迟生成及取消；弱引用托管和 generation/round 使旧局回调失效。
- 归零到真正死亡/复活处理之间不抢跑。普通 Creature 没有 Ball 的死亡解析器，不能仅凭未进入Die就无限续命。
- Runtime存续查询与主角色布阵计数分离，保留原计数/快速存在查询的精确性能契约。
- 1v1先按存续组记录胜负，再清理所有旧成员与旧请求；车轮只换真正灭绝的一侧，挑战仍按原蓝方尝试规则结算。
